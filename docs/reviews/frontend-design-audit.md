# Frontend Design Audit

日期：2026-04-29  
审查视角：`frontend-design`，目标是生产级、独特、可用、可推进的社交推理游戏界面。

## 审查范围

- 入口页：`/`
- 等待室：测试/单人调试自动补 AI 后的等待状态
- 角色揭示 Overlay
- 游戏主界面：提名、投票、任务谜题、任务揭晓前后状态
- 单人调试面板
- 独立教程页：`/tutorial.html`
- 代码结构中存在但入口不完整的页面/面板：`helpPanel`、`tutorialPanel`、`finishedScreen`、loading/disconnect overlay
- 桌面宽度与移动宽度抽查

## 总体判断

当前界面有明确方向：复古像素 + 社交推理 + 系统维护谜题。这是可成立的产品气质，但执行不稳定。入口页有记忆点，游戏内页面却退化成未完成的调试界面：布局重心散、控件样式断裂、移动端溢出、部分页面无入口。作为可演示原型可以跑通，但还没有达到“可邀请玩家完整体验一局”的前端质量。

## P0 阻断体验问题

### P0-1 游戏主界面布局失衡

桌面游戏页三栏布局没有形成清晰重心：

- 中间舞台区域大面积空置，真正需要操作的任务谜题却挤在左下。
- 左侧任务信息、投票历史、谜题和聊天混在一起，用户很难判断当前最重要动作。
- 右侧玩家列表距离主操作区太远，社交推理信息和投票/任务上下文割裂。

建议：重建游戏主界面信息架构。桌面用“中间主操作区 + 左侧状态/历史 + 右侧玩家/身份线索”；移动端改为单列卡片流，不要压缩三栏。

### P0-2 移动端游戏页不可接受

移动宽度下任务阶段出现明显可用性问题：

- 任务选项横向溢出，按钮显示为浏览器默认样式。
- 顶部阶段状态块过大，挤压核心操作区。
- 玩家列表、聊天、任务题目堆叠混乱，文本过大且换行不可控。
- “玩家”标题被拆成两行，说明布局没有为窄屏建立稳定约束。

建议：移动端单独设计，不复用桌面三栏。任务题目、选项、聊天、玩家列表应分为可折叠或顺序卡片。

### P0-3 任务谜题按钮样式断裂

任务选项 `A/B/C` 在桌面和移动端都呈现为默认 HTML 按钮，和整体像素风、蓝紫边框系统完全不一致。这是玩家当前最关键的操作，却视觉上最像未设计控件。

建议：把谜题选项做成全宽选择卡，包含选项字母、方案标题、风险提示、选中态、禁用态、提交态。

### P0-4 投票历史暴露长 ID 并撑破面板

投票历史显示 `socket id` / AI 内部 ID，桌面左侧面板出现长字符串溢出。玩家需要看到“谁被提名、谁投了什么”，不是技术 ID。

建议：所有玩家引用统一使用昵称；历史记录用 compact row，例如“第1轮：桌面审查、AI_小红 · 6:0 通过”。

## P1 高优先级设计问题

### P1-1 入口页桌面构图不均衡

桌面入口页右上角模式按钮过于远离表单，左侧大面积空白。视觉焦点被拆成“右上按钮”和“中间表单”两个互不关联的区域。

建议：模式选择应靠近房间号/开始按钮，作为表单的一部分；桌面首屏可保留宽屏氛围，但内容容器要集中。

### P1-2 入口模式按钮在窄屏过挤

三种模式恢复后，在窄屏横排会挤压。按钮文字长，图标 + 文本占位大。

建议：小屏改为 3 段式纵向或两行 segmented control；正常模式默认居首，测试/单人调试弱化为辅助入口。

### P1-3 教程页与游戏主视觉不一致

`/tutorial.html` 像一篇静态说明文档，缺少游戏内视觉语言的结构化表达。它仍有较强“文档卡片”感，和入口的像素/街机气质没有形成产品级统一。

建议：教程页改成“规则手册/任务终端”风格，使用流程图、角色卡、胜利条件条，不要长段文字堆叠。

### P1-4 教程内容仍混用旧规则表述

独立教程页仍出现“破坏任务”“投破坏票”等旧阿瓦隆表述；当前游戏已转向系统维护谜题/正确修复方案。

建议：统一改为“选择错误方案/诱导错误修复”，避免玩家以为任务阶段是普通成功/破坏投票。

### P1-5 游戏内帮助面板和内置教程没有入口

代码里有 `helpPanel`、`tutorialPanel`、`showHelp()`、`showTutorial()`，但当前可见 UI 没有稳定入口。入口页“游戏教程”直接打开独立页面，游戏中没有可发现的帮助按钮。

建议：游戏顶部加入小型帮助按钮；等待室和游戏中都可打开同一套轻量规则面板。

### P1-6 单人调试面板遮挡核心游戏

单人调试面板是一个大浮层，移动宽度下直接遮挡任务题目和聊天。调试工具本身视觉完成度高于游戏主操作区，抢占注意力。

建议：调试面板默认折叠为右下工具按钮；展开后使用抽屉，不覆盖当前任务核心区域。

### P1-7 角色揭示 Overlay 可读但节奏粗糙

角色揭示能传达身份，但它覆盖等待室时背景过暗，且“点击任意处继续”不够像明确按钮。玩家可能不知道是否可跳过或何时进入游戏。

建议：加入明确主按钮“进入本局”，同时展示一条本角色本局目标。

## P2 中优先级细节

### P2-1 H1 可访问名称重复

入口页 H1 在无障碍树中读作“谁是AI 谁是AI 谁是AI”，是 glitch 视觉层造成的语义重复。

建议：装饰层加 `aria-hidden="true"`，真实 H1 只保留一次。

### P2-2 Emoji 与像素风混用过多

当前 emoji 大量用于状态、角色、按钮、提示，和像素小人/复古字体混搭后显得噪声偏高。

建议：保留少量角色/模式 emoji，核心操作和状态尽量用统一图标或像素化符号。

### P2-3 字体尺寸缺少场景约束

移动端游戏页正文和按钮文字过大，桌面教程页正文又偏像大字报。缺少 “标题/面板标题/正文/操作控件/辅助信息” 的层级规范。

建议：建立 typography scale，移动端正文与按钮单独设定，禁止核心文本因父容器缩小而溢出。

### P2-4 Loading、断线、结算页面未形成完整体验闭环

代码里有 loading/disconnect overlay 和丰富结算结构，但视觉和入口关系不清晰。结算页有统计、MVP、反馈、分享，但缺少和本局关键事件对应的叙事主线。

建议：结算页优先展示“胜负原因 + 关键三轮 + 角色揭示”，统计和反馈后置。

## 建议改造顺序

1. 先重构游戏主界面响应式布局，解决桌面/移动端 P0 可用性。
2. 统一任务谜题卡片和按钮样式，恢复关键操作的产品质感。
3. 清理投票历史/玩家引用，禁止内部 ID 出现在 UI。
4. 整合帮助、教程、规则文案，保证“系统维护谜题”规则一致。
5. 调整入口页构图和模式选择，在桌面/移动端都稳定。
6. 最后处理结算页、调试面板、无障碍和图标体系。

## 优化进展

2026-04-29 第一轮已处理：

- 修复 `style-v3.css` 中 `.team-member` 规则缺失闭合导致的游戏界面样式解析错位。
- 游戏主界面改为更稳定的桌面三栏布局，主操作区承载舞台、谜题和聊天。
- 移动端改为单列流，隐藏未初始化的舞台空白区，任务谜题优先展示。
- 任务谜题 `A/B/C` 改为选择卡样式，避免默认浏览器按钮。
- 投票历史通过客户端玩家名映射显示昵称，避免暴露 socket/AI 内部 ID。
- 游戏页切换时给 `body` 标记当前屏幕，取消旧全局居中样式对游戏页的裁切影响。
- 移动端操作栏固定到底部，避免投票/提名动作掉到长页面下方。
- 游戏顶部补充帮助和规则入口。
- 独立教程页清理旧“破坏票/任务成功”表述，统一到系统维护谜题。
- 入口 H1 调整无障碍语义，避免读屏读出重复标题。
- 小屏入口模式按钮改为纵向排列，避免三模式按钮挤压。
- 单人调试面板默认折叠，避免初始遮挡核心游戏操作区。

2026-04-30 第二轮已处理：

- 入口页改为桌面左右信息架构，模式选择回到表单区域，正常模式恢复为默认首选入口。
- 覆盖旧全局 `body` 固定高度/隐藏溢出规则，解决入口首屏在桌面高度不足时标题被裁切的问题。
- 独立教程页改为“任务终端/规则手册”视觉结构，和游戏内深色像素终端气质保持一致。
- 单人调试面板改为游戏页右侧折叠抽屉入口，默认不遮挡任务谜题和聊天。
- 结算页按“胜负原因 -> 任务复盘 -> 角色揭示 -> 统计/反馈”调整叙事优先级。
- 桌面和移动端用浏览器抽查入口、教程、单人调试游戏页，核心操作未见挤压或重叠。

仍可后续增强：

- emoji 图标体系还没有替换为完整的自定义像素图标库；当前只做了布局收敛和噪声控制。
- 角色揭示 Overlay 可进一步补强“进入本局”的明确 CTA 和角色目标一句话。
