# 多 Agent 用户体验迭代记录

日期：2026-04-30

## 目标

使用多个体验 agent 模拟真实用户路径，记录问题，再由执行工程师 agent 修复。修复后体验 agent 复评打分，直到关键体验达到满意线。

满意线：

- 总评分 >= 8/10。
- 无 P0 阻断问题。
- P1 问题不影响完成首局体验。

## 体验角色

- Agent A：第一次接触游戏的新手玩家。
- Agent B：派对房主/组织者，负责解释规则并开局。
- Agent C：手机端/小屏玩家。

## 第一轮体验结论

### Agent B：派对房主/组织者

评分：4/10  
结论：不满意。作为房主，“快速解释规则并开局”的核心链路不可靠，正常模式尤其会卡住。

核心判断：

- 正常模式没有可靠的“房主开始游戏”入口。
- 三种模式的真实能力和文案不完全一致。
- 人数、轮数、发言次数在 README、页面、服务端之间不一致。
- 分享房间没有携带房间号和模式，朋友加入成本偏高。
- 测试/单人模式无法真实验证渗透者破坏和 AI 附身，因为 AI 没有阵营策略。

## 第一轮问题清单

### P0-1 正常模式没有可靠开局/推进路径

复现路径：

1. 选择正常模式。
2. 输入昵称和房间号进入等待室。
3. 即使朋友都加入，也没有房主“开始游戏”按钮。

证据：

- `client/index.html` 的“开始游戏”只调用 `joinGame()`。
- 客户端没有稳定入口触发 `socket.emit('startGame')`。
- Go 服务端虽然注册了 `startGame`，但 UI 不触发。
- 自动推进目前只对 `test/solo` 生效。

建议：

- 等待室加入房主身份和“开始游戏”按钮。
- 达到最低人数后允许房主开始。
- 对当前阶段推进采用统一策略：要么服务端计时自动推进所有模式，要么 UI 明确给行动入口。

### P1-1 三种模式心智不清

问题：

- 测试模式和单人调试都会自动补 AI 并开始。
- 单人调试显示调试面板，但相关服务端 handler 不完整。
- README 对测试模式写“可跳阶段、加速”，实际 Go 链路不完全支持。

建议：

- 正常模式：真人房主开局。
- 测试模式：自动补 AI，自动跑流程，用于流程演示。
- 单人调试：自动补 AI，并且只展示真实可用的调试功能；未实现按钮先隐藏。

### P1-2 人数与规则描述冲突

问题：

- 首页写 6 人局。
- 等待室固定显示 `/6`。
- README 写普通模式 2-6 人。
- 服务端实际 `MinPlayers=5`、`MaxPlayers=8`。

建议：

- 本阶段先统一为“5-8 人，推荐 6 人”。
- 等待室显示“当前 X / 最低 5，最多 8”。
- 首页保留“推荐 6 人局”，不要写死全部模式只能 6 人。

### P1-3 分享房间不可靠

问题：

- 分享文案只包含房间号。
- URL 不携带 `room` / `mode`。
- 朋友打开后还要手动填房间号和模式。

建议：

- 分享 URL 使用 `?room=xxx&mode=normal`。
- 页面加载时读取参数并自动填入房间号、模式。

### P1-4 阿瓦隆投票规则偏差

问题：

- 平票会通过。
- 连续否决没有明确惩罚或 UI 说明。

建议：

- 改为严格多数通过，平票否决。
- 连续 5 次否决给渗透者阵营胜利，或在 UI 明确这是自定义规则。

### P1-5 测试/单人模式无法验证渗透者破坏

问题：

- AI 没有角色/阵营。
- AI 队伍票默认同意。
- AI 任务行动默认选 A。

建议：

- 测试/solo 的 AI 也分配角色。
- 渗透者 AI 在任务阶段按概率选择高风险方案。

### P1-6 AI 附身机制未完整落到 Go 核心流程

问题：

- Go 聊天处理只广播原消息。
- `playerName` 可能不稳定。
- 未看到完整 `possessionAlert/signalCheck` 服务端链路。

建议：

- Go 服务端处理聊天计数、玩家名、附身改写、侦测者提示。
- 如果暂不实现，弱化首页对“AI 附身干扰”的承诺。

### P2-1 房主口播规则缺失

建议新增等待室短规则：

> 每轮队长提名小队，全员投票；通过后小队选择行动方案。稳妥行动让守护者得分，高风险行动让渗透者得分，先到 3 分获胜。

## 第二轮体验补充

### Agent A：新手玩家

评分：6.5/10  
结论：不满意。核心路径能进入游戏，但新手仍容易把执行阶段理解成“答题”，不是社交推理里的隐藏身份对抗。

问题：

- 执行阶段揭晓仍强调“稳妥方案 A”和对错符号，导致失败像玩家答错题，而不是渗透者推动了高风险行动。
- 角色揭示只告诉身份，没有告诉玩家接下来该做什么。
- 单人调试自动推进过快，新手看不到“我该观察什么”。
- 教程页仍把护卫、伪装者等扩展能力写成当前可操作能力，和 Go 链路不一致。
- 首页和帮助文案缺少“这不是答题游戏”的心智说明。

### Agent C：手机端玩家

评分：6.5/10  
结论：不满意。手机端能进入局内，但状态信息和操作区的空间处理影响流程判断。

问题：

- 手机端局内先看到任务/聊天，当前轮次、队长、任务进度在后面，玩家容易不知道自己处于哪一步。
- 底部操作栏即使没有可用操作也占空间，导致页面有空白压迫。
- 单人调试面板在手机端缺少稳定 fixed 行为，容易遮挡或随内容流动。
- 登录表单在小屏上边距过窄。
- 教程弹窗缺少小屏高度保护。
- 等待室 8 个空槽在手机端太长，真实玩家和开局按钮被稀释。

## 第二轮修复计划

- 手机端局内排序改为状态 → 主内容 → 玩家列表。
- 操作条根据实际可用操作显示/隐藏，并同步 body 底部留白。
- 手机端调试面板、登录表单、教程弹窗和等待室空槽做布局修复。
